# v5.0 — the console redesign (detailed design)

**Theme:** the left rail stops being a permanent compose form and becomes a **navigator**;
launching becomes a **focused action**. This is the milestone that earns the major bump.

Today `<aside>` (board.ts ~628) is three stacked blocks — **Context** (machine/repo selects +
Browse/New/Path/⎇/× buttons), **Start** (a ~12-field launcher form, always present), and
**Library**. The launcher dominates the rail even though you launch occasionally; there's no
navigation (Active/Archive live in the header, `#viewSeg` ~618); repos are a `<select>`, not a
scannable list; and the board never scopes to a repo (`taskRepo` is only the launch target).

**Approved direction (Direction A)** — mockup with the maintainer (`scratchpad/
coxpit-sidebar-artifact.html`, and the hosted artifact). Build order per this spec:
**rail → sheet → mobile → adjacent polish → folded fixes.**

Reuse over rewrite: the launcher's existing controls (`#launchTabs`, `#taskForm`,
`#panelTask/Goal/Bench`, provider/mode segs, count, submit) **move** into the sheet unchanged —
this is relocation + progressive disclosure, not a logic rewrite. The view logic (`?view=`,
`/api/fleet`, `/api/archive`) is reused; only its *entry point* moves to the rail.

Ships as **5.0.0**, developed as e2e-green commits on main (one per Part), then cut once the
redesign lands. Design-as-Fable / build-as-Opus continues.

## Part A — the navigator rail (Phase 1)

Replace the `<aside>` Context + Start blocks with a navigator. Keep Library (collapsible) at
the bottom or fold it behind Options later.

### A1. Structure & markup
```
<aside class="rail">
  <button class="machine" id="machineSwitch">⛁ local ●</button>   ← compact, opens the machine menu
  <p class="rlabel">Repositories</p>
  <div id="repoList"> … .repo rows … </div>                       ← A2
  <button class="repo add" id="repoAdd">＋ Add repository…</button>← A6
  <p class="rlabel">View</p>
  <nav id="viewNav"> Active · Goals · Archive </nav>              ← A5 (moved from header)
  <div class="railsp"></div>
  <button class="newbtn" id="newBtn">＋ New</button>              ← opens the sheet (Part B)
  <details id="libraryBox"> … design captures + bookmarklet … </details>
</aside>
```
Classes/tokens per the mock (`.rail`, `.machine`, `.repo`, `.repo .cnt`, `.navi`, `.newbtn`).
Icons via the Lucide sprite (server, folder, plus, layers, target, archive).

### A2. Repo list + per-repo signals (client-side)
- Render one `.repo` row per registered repo (from the fleet/repos payload). Each row:
  folder icon · name · **active-run count badge** (`.cnt`) when > 0 · an **attention dot**
  when the repo has a failed/errored run needing a hand.
- Counts are **computed client-side** from the existing `/api/fleet` active runs grouped by
  `task.repoId` — **no new endpoint**. (If the fleet payload doesn't already carry `repoId`
  per run/task, add it to the fleet task shape — it's already in the DB.)
- The selected repo row is highlighted (`.repo.on`); persist the selection in
  `localStorage('coxpit.repo')`.

### A3. Repo scoping (new behavior)
Selecting a repo **scopes the board to it** — the Active/Goals views render only that repo's
runs/groups. Implement as a **client-side filter** on the already-loaded fleet (filter cards by
`repoId === selectedRepo`); add an **"All repositories"** pseudo-row (or a header affordance) to
clear the scope. The launch target (Part B) defaults to the scoped repo. (No server change;
`/api/archive` already accepts `?repo=` for the Archive view.)

### A4. Machine switcher
Replace the machine `<select>` with a compact `.machine` button showing the current machine +
a reachability dot; clicking opens a small menu of machines (reuse the machines list + probe
state already in the header `.machines`). Scoping repos to the machine as today.

### A5. View nav (move from header)
Move `#viewSeg` (Active/Archive) out of the header into the rail as `#viewNav`, and **add
Goals**:
- **Active** — active runs (flat), repo-scoped by A3. Reuses `/api/fleet?view=active`.
- **Goals** — the group bands only (plan-fanout/swarm groups = the converge entry). Client-side
  filter of the active view to grouped tasks, rendered as the existing group bands.
- **Archive** — the existing archive list (`/api/archive`), repo-scoped.
Each shows a count. The header keeps live/notify/remote; the view switch now lives in the rail.

### A6. Add-repo flow + empty state
Fold Browse / New / Path into a single **"＋ Add repository…"** that opens a small menu (or the
existing Browse picker with New/Path inside it — the Browse modal already hosts New-folder). Per-
repo actions (base-branch ⎇, remove ×) move to a **row hover/context menu** on `.repo`. Empty
state: no repos → the rail shows "Add your first repository" wired to the readiness panel.

**Phase-1 DoD:** rail renders repo list with live count badges + scoping, machine switcher, and
the moved Active/Goals/Archive nav; the launcher still works (temporarily kept or already moved
in the same PR); board scopes to the selected repo. e2e: board serves `#repoList`/`#viewNav`,
counts reflect active runs, scoping filters cards.

## Part B — launch as a New sheet (Phase 2)

`＋ New` opens a focused compose **sheet** (an overlay, same `.overlay` pattern) instead of the
permanent rail form.

### B1. Sheet shell
`#newSheet` overlay → a `.sheet` card: header (`＋ New · <selected repo>` + ×), a **type seg**
`Task │ Goal │ Workbench` (reuse `#launchTabs` semantics), the type body, and a footer.

### B2. Move the launcher in (reuse, don't rewrite)
Relocate `#taskForm` + `#panelTask/#panelGoal/#panelBench` + provider seg + mode seg + count +
submit **into the sheet body**. The existing submit handler already branches on the active tab —
keep it. Type body per the mock:
- **Task** — title, prompt, "From GitHub", provider seg; then a progressive **"Options"** reveal
  (chevron) holding **model · design capture · deliverables** (the fields that are rarely used).
  Footer: Dry/Real · count · **Run fleet**.
- **Goal** — the goal textarea + provider; footer: Dry/Real · **Plan & run** (no count — the
  planner decides).
- **Workbench** — optional name + the explainer; footer: **Open workbench** (no mode/count).
Footer button label + visible controls adapt to the active type (as the mock's `setV` shows).

### B3. Target repo & open paths
The sheet's target repo = the rail's selected repo (shown in the header). `＋ New` (rail) opens
Task by default; the type seg switches within the sheet. Optional later: `＋ New ▾` split menu
for a one-click type shortcut (Part D).

### B4. Progressive disclosure
`model · optional`, `design capture · optional`, `deliverables · optional` collapse under
"Options — model · design · deliverables"; expanded state remembered per session. Deliverables
chips render in **English** (Answer/Code/Doc/Page/File) — see the English sweep (Part D).

**Phase-2 DoD:** the rail form is gone; `＋ New` opens the sheet; all three types launch exactly
as before (dry e2e settles for Task + Goal + Workbench from the sheet); Options disclosure works.
e2e: board serves `#newSheet` + the type seg; a dry Task/Goal launched via the sheet endpoints
settles (the API is unchanged, so mostly a UI-contract + one launch check).

## Part C — pocket board (Phase 3)
The mobile drawer becomes **just the navigator** (machine + repo list + view nav); a floating
`＋` **FAB** opens the compose sheet (full-bleed on mobile). Fixes the "dense form crammed into a
drawer" problem (the current `#menuBtn` drawer holds the whole launcher). Reuse the v3.6 mobile
drawer plumbing; the sheet is already an overlay → full-bleed via the existing mobile modal CSS.

**Mobile stability — kill the left-right jitter (reported on the PWA).** The root has no
horizontal-overflow / overscroll guard (`html,body{height:100%}` only, board.ts ~25), so on
mobile the page pans and rubber-bands left-right whenever any element nears/exceeds 100vw or the
off-canvas drawer (`aside{position:fixed;transform:translateX(...)}` ~650) leaks — it feels
"not like an app." Harden:
- `overscroll-behavior: none` on the root (kills the iOS horizontal rubber-band) + clamp
  horizontal overflow **carefully** — prefer `body{overflow-x:hidden}` / a wrapper, NOT `html`
  (`overflow` on `html` can break iOS `position:fixed`/sticky — the header + drawer rely on it).
- Audit for any element wider than the viewport (wide diffs/code/tables must scroll inside their
  own `overflow-x:auto` container — most already do; find the offender by width probe).
- Ensure the hidden drawer (translateX off-screen) is not part of the scrollable width.
- Verify standalone-PWA (`display-mode: standalone`) + `viewport-fit=cover` safe-area insets.

**Login-page hardening (folded in — reported mobile Safari):** unlock succeeds (200 + cookie)
but mobile Safari doesn't commit the fetch-response `Set-Cookie` before `location.replace('/')`
→ refreshes back to login (iPad + home-screen PWA work). Fix in `login.ts`: replace the
fetch-then-`location.replace` success path with a **real form POST navigation** (browser applies
`Set-Cookie` on the navigation response), or fetch with explicit `credentials:'same-origin'`
then a hard `location.href='/'`. Also add `autocapitalize="none" autocorrect="off"
spellcheck="false"` to the key input and surface the rate-limit "try again in Ns" clearly.

## Part D — adjacent polish & folded fixes (Phase 4+, each its own commit)

- **⌘K command palette** — a modal launcher: switch repo, New task/goal/workbench, jump to a run
  by id/title. Keyboard-first; high-leverage for a repetitive cockpit. (New `#palette` overlay +
  a fuzzy filter over repos/runs already in memory.)
- **Active vs Goals boundary** — finalize: Active = all active runs flat; Goals = group bands;
  Archive = closed. (Mostly A5; this is the copy/behavior polish.)
- **Collapsible rail** — a toggle collapses `.rail` to icon-only (VS Code activity-bar style) for
  max board space; persist in localStorage.
- **Repo-row status signals** — the active-run badge (A2) plus an attention dot when a repo has
  failed/dirty work.
- **Empty-state onboarding** — no repo → rail CTA (A6).
- **`＋ New ▾` split menu** — optional one-click type shortcut beside the sheet tabs.
- **Compare AI review has room (FIX)** — today `#cmpReview` (board.ts ~834) is a band above the
  diff columns with **no dedicated scroll/height** (`.cmp-review` ~483 is typography only), so a
  long review (approaches/pros-cons/recommendation) is cramped and hard to scroll. Give it its
  own space: either a **full-height, scrollable review pane** (own `overflow:auto; max-height`)
  that **replaces** the diff columns while open, or **reuse the Answer output-viewer** pattern.
  Toggle back to the diffs. No more tiny band.
- **English sweep (FIX)** — the deliverables/contract + converge labels leaked Korean from the
  design mocks. Normalize to English since the product ships in English: `요청 산출물(계약)` →
  "Required outputs (contract)", `요청됨/부수` → "Required/Extra", chips `답변/코드/문서/페이지/
  파일` → Answer/Code/Doc/Page/File, converge `리뷰/수정/머지/클로즈` → Review/Steer/Merge/Close,
  `산출물` → "Outputs". Mechanical; do it alongside the sheet (same board.ts).

## Guardrails
- `board.ts` is one template literal (`\n`, escaped backticks, esc()/escA()). The rail + sheet
  are large moves — keep it valid; the e2e board-serve checks catch a SyntaxError.
- No new deps; icons from the v4.8 Lucide sprite. No native select/alert/confirm.
- Reuse the existing launch/fleet/archive APIs — repo scoping and per-repo counts are
  **client-side** (no new endpoints unless the fleet task shape lacks `repoId`, in which case add
  that one field). Don't regress dry-run, the workroom, or archive-open.
- Update `DESIGN.md` for every new component (rail, repo row, view nav, New sheet, palette).

## Definition of done
The rail is a navigator (machine + scannable repo list with live counts + scoping + view nav);
launching is a focused Task/Goal/Workbench sheet with progressive options; mobile is drawer-nav +
FAB; the compare review has real room; labels are English. Then **5.0.0** is cut via the standard
train (bump both package.json + desktop, locks, tag, hardened CI, owner npm publish, resident
upgrade). The palette / collapsible rail / split menu may trail into 5.0.x if 5.0 is cut on the
core redesign — decide at cut time.
