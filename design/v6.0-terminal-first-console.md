# v6.0 — the terminal-first console (detailed design)

## Why a major

Two truths collided and this release resolves them.

**Truth 1 — usage.** The maintainer's daily surface is the terminal, full stop. The board,
fleets, swarm, review judge, Design Mode: unused. Sessions get named after *projects*
("coxpit-oss") because the flat session list offers no project level — naming is compensating
for a missing hierarchy. A session's name should be the *work* ("기능 업데이트 6.0"), under
the project it belongs to, with the agent terminals under that.

**Truth 2 — the model already agrees.** Coxpit's data model *is* that hierarchy:
**Repo = project · Task = work · Run = agent session** (runs already carry provider + model;
tasks already carry titles; the flat "Sessions" area is just runs in the `kind='sessions'`
bucket repo). What's missing is not a model — it's that the cockpit hides the hierarchy
behind fleet ceremony (compose forms, fan-out counts) instead of surfacing it as the way you
*organize terminals*.

So v6.0 is an identity release: **the cockpit becomes the console, organized as
Project ▸ Work ▸ Session; the board recedes to a review-and-records room.** The fleet stops
being a destination and becomes what naturally happens when you add a second agent to a work.

```
Scratch (공용)                    ← today's flat sessions: ideas not yet a project
coxpit-oss                        ← Repo (project)
 └ 기능 업데이트 6.0               ← Task (work) — names live here now
    ├ main   (my hand terminal)   ← run, checkout, no agent
    ├ 구현 · opus                  ← run, agent, in-place or worktree
    └ 기타 · opus                  ← run, agent
```

## Locked decisions

- **D1 — the tree**: cockpit workspace tree = Scratch first, then Project ▸ Work ▸ Session.
  Session names are work-part names (roles), never project names.
- **D2 — a work opens with a hand terminal**: creating a work immediately opens a `main`
  terminal **at the repo checkout** (root-session semantics — the terminal-first flow the
  maintainer already lives in). No agent, no worktree, no merge affordances.
- **D3 — isolation is a choice, not a default**: adding an agent session asks *where*:
  **in-place** (the repo checkout — sequential collaboration, file context shared by virtue of
  being the same tree) or **worktree** (parallel attempts, experiments, compare/merge later).
  Guard: **at most one live in-place *agent* per repo** (two agents editing one checkout
  collide); hand terminals are unrestricted (the human's choice).
- **D4 — WORK.md, the work's shared context**: one markdown file per work — goal, decisions,
  constraints. Edited in the cockpit, injected into every agent launched under that work.
  Closes the context silo between isolated runs (a worktree branches from base *before* a
  sibling's changes; a run's claude session never hears what you told another one).
- **D5 — Scratch and promotion**: the sessions bucket is reframed as Scratch (공용) — the
  idea stage. Two promotion paths: *this folder grew up* → register it as a repo (existing
  flow) and the work re-parents; *this work belongs to a project* → re-parent the task.
- **D6 — the board is demoted, not deleted**: cockpit is the only home. The board keeps
  working as the review/records room (archive browsing, goal workrooms, share management) but
  its growth freezes: new capabilities land in the cockpit. Absorption of remaining board
  views into cockpit panes is 6.x, evidence-permitting.
- **D7 — v5.28 Part A rides this tree**: agentstate phases 1–2 (detection + transport,
  [v5.28 spec](v5.28-agent-terminal-flow.md)) are tree-independent and may land first; the
  surface phase (Agents rail, tab dots) lands grouped **by Project ▸ Work**, not as a flat list.

## Part T — the work tree (`src/cockpit.ts`)

### T1. Tree structure
`renderTree()` reorganizes to: **Scratch** section (sessions-bucket runs, unchanged data) →
one section per registered repo → its tasks (works) → each task's runs (sessions). Machine
scoping stays as-is. Groups/goals, when present, render as a thin band inside their repo
section (no new concept). Board-launched fleet tasks appear identically — they *are* works.

### T2. New work
A `＋ 새 작업` affordance on the repo node → prompt for the work name → `openWorkbench(repoId,
title, root=true)` (exists — orchestrator.ts:1059): creates the task and a root-session run at
the checkout, opens its terminal focused. That run displays as **main**.

### T3. Add an agent session
`＋ 에이전트` on the work node → small sheet: **role name** (free text, e.g. 구현),
**provider** (claude/codex seg, existing), **model** (existing input), **place**
(`in-place | worktree`, D3). Worktree → the existing run-launch path under this task
(attempts, compare — all current machinery). In-place → Part P.

### T4. Names
- Work name = `tasks.title` (rename exists).
- Session role = **new column `agent_runs.title`** (text, default `''`; display falls back to
  the provider name). Rename via the existing tab double-click flow, PATCH `/api/runs/:id`.
- Tab label = `role` when short, `work · role` when the pane header has room (existing
  `tabName()` seam).

### T5. Session restore
`coxpit.session` snapshots store runIds already; the tree regroup does not change restore.
e2e keeps the existing restore check green.

### T6. Hygiene — the list must be cleanable from where it clutters
Born from a real cleanup session (2026-09-17: a duplicate repo registration, five
experiment repos with zero live work, eight month-old experiment tasks, and 13 orphaned
`coxpit-r*` tmux sessions — all removed by hand through the API). The tree gets the same
power:
- **Project node → "등록 해제"**: repo DELETE behind a confirm that states what it is
  (registration only — the folder on disk is untouched, re-registering is one click) and
  aggregates the close-guard over any still-open works.
- **Project node → "묵은 작업 정리…"**: lists that repo's non-closed tasks with settled
  runs, unmerged-output warnings aggregated (the v4.1 guard, shown once as a table, not N
  dialogs), checkboxes, one close pass.
- **Orphan tmux reaper**: a maintenance action (♻ family, next to Reclaim worktrees) that
  lists `coxpit-r*` tmux sessions with no matching run record — kill selected. Panes running
  more than an idle shell are flagged, never preselected.

### T6b. Worktree disk pressure — make the debt visible and reclaimable *(spec ready — deferred, follow-up to T6)*

Every non-in-place run is a `git worktree` under `<repo parent>/.coxpit-worktrees/rN`, and for
a Next/Electron repo that worktree carries a full `node_modules` copy — **~180MB each**
(measured in v4.7). Many projects × many runs is real GB of debt. Normal flow already contains
it (merge/close → `cleanupRun` removes the worktree + branch; the ♻ Reclaim action sweeps
orphans that are *not live and* closed/failed/stopped — never running/done). The gap is
**done-but-never-merged/closed runs**: their worktree lingers, Reclaim deliberately won't touch
`done` (safety), and the cockpit shows *no size anywhere* — so the debt is invisible until the
disk is full (lived it 2026-09-17, data volume at 99%). Fix:

- **Show the number.** A one-line disk readout in the ♻ maintenance surface (and `/api/health`
  on darwin/linux): total `.coxpit-worktrees` size + count, like `docker system df`. Cheap
  `du -sh` on the worktree parent(s), cached briefly. You can't manage what you can't see.
- **Reclaim reaches `done`, with a guard.** Extend `listReclaimableWorktrees` to offer `done`
  runs *whose net work is already merged or exported* (reuse the v4.1 close-guard /
  `taskCloseRisk` signal). A `done` run with **unmerged, un-exported** changes is listed but
  **flagged and never preselected** (its worktree is the only copy of that work — deleting it
  is data loss). Merged/exported `done` worktrees preselect freely.
- **Honesty rule (carried):** never reclaim a worktree that is the sole copy of unmerged work
  without the human ticking it past a clear warning; `running` is never touched.
- Keep it terminal-only, no new deps; `du` is the only new cost and it's on-demand.

Why deferred: T6 shipped the project/scratch/tmux hygiene; this is the *disk* axis of the same
"cleanable from where it clutters" principle, sized as its own follow-up so it isn't rushed
into the 6.0 cut. Natural companion to v5.28 Part B (stale-process guard) and Part D.

## Part P — in-place agent sessions (`src/orchestrator.ts`, `src/server.ts`)

### P1. Mechanism (reuse the root-session convention)
An in-place agent run is a normal run whose `worktreePath = repo.path` and `branch = ''` —
**exactly the existing root-session marker** (orchestrator.ts:1961 already treats
`!run.branch || worktreePath === repoPath` as "not an isolated worktree"). Launch flag
`inPlace: true` on the run-creation API skips worktree/branch creation and spawns the agent
with `cwd = repo.path`. No schema change beyond `agent_runs.title` (T4).

### P2. Affordances follow the marker
Merge / PR / Integrate / Sync-base are hidden for in-place runs (nothing to merge — edits land
in the checkout directly, visible live from the `main` terminal). Diff button shows the
checkout's working diff (`git diff` at repo.path) labeled honestly as *uncommitted changes*,
not a run-scoped diff. Stop/steer/resume unchanged (same process-group semantics).

### P3. The one-live-in-place guard
Launching an in-place agent while another in-place agent run on the same repo is live → 409
`{ error: 'IN_PLACE_BUSY', detail: 'r<N> is already working in this checkout — steer it, or launch in a worktree' }`.
Hand terminals never count. The sheet (T3) surfaces the reason inline.

### P4. Honesty in the UI
The place choice states the tradeoff in one line: *in-place = shared context, sequential ·
worktree = parallel, merge later.* No pretending both at once.

## Part W — WORK.md, the work's shared context

### W1. Storage
Canonical file per work: `~/.coxpit/work/<taskId>.md` (daemon data dir — outside every git
tree, so no diff pollution and no branch skew). Created on first edit; deleted with the task.

### W2. Cockpit editing
The work node gets a `📝 WORK.md` entry → opens in the existing file-viewer pane in edit mode
(files.ts is jailed to home, which contains `~/.coxpit` — no new surface). The `main`
terminal's owner curates it: goal, decisions, constraints.

### W3. Injection
Every agent launched (or steered) under the work gets a prompt block, same seam as DESIGN
CONTEXT:

```
## WORK CONTEXT (shared across this work's sessions — decisions recorded here bind you)
<file contents>
```

Injected at launch and on steer; the UI states plainly that **mid-flight edits reach the next
launch/steer**, not a running turn (no magic).

### W4. Harvest (phase 2 of this part — optional, honest)
Live runs may append decisions to `.coxpit/WORK.md` in their own worktree; the existing
1.5s file watcher (spawn.json cadence) harvests **append-only** lines into the canonical file,
provenance-tagged (`— r12`). Append-only sidesteps merge conflicts. If this proves noisy in
dogfooding, it stays off — injection alone already carries the human-curated context.

## Part S — Scratch & promotion

### S1. Reframe
The sessions bucket renders first as **Scratch** with one line of copy: *ideas before they're
projects*. Data unchanged (`kind='sessions'`).

### S1b. Scratch hygiene
Same cleanability at the scratch level: a "정리…" affordance on the Scratch header lists
sessions with liveness (tmux alive? last activity when?), stale/dead ones preselected, one
delete pass (deleteSession — the folder is always preserved, stated in the dialog). Sessions
older than ~14 days with no activity fold under a collapsed "오래된 세션 N" row so the list
stays scannable without deleting anything.

### S2. Promotion
Context menu on a scratch work:
- **"프로젝트로 등록"** — the session's folder becomes a repo: reuse the existing Register
  flow (path prefilled), then re-parent the task to the new repo.
- **"프로젝트로 이동"** — pick an existing repo; `PATCH /api/tasks/:id { repoId }` re-parents.
  If the session's folder lies outside the repo path, warn (organization changes, the terminal
  keeps its folder — stated, not hidden).

## Part B — the board recedes

- **Policy, mostly**: cockpit is the home on every surface (desktop already defaults to
  `/cockpit`; landing + README reposition to terminal-first — folds into the pending public
  write-up, with the measured-vs-stub contrast as the thesis). New capabilities land in the
  cockpit; the board gets fixes only. Stated in ROADMAP Non-goals/positioning.
- **Entry points**: ⌘K gains `Board`, `Archive`, `Workrooms` commands that open the board's
  views — the reading room is one keystroke away, never the front door.
- **Nothing is removed.** Fleet-first outside users lose nothing; absorption of archive/
  workrooms into cockpit panes is 6.x, only with evidence.

## Phasing (each an e2e-green commit; no build step; single-file cockpit stays)

1. **T — tree regroup** + 새 작업/＋에이전트 affordances (worktree mode only) +
   `agent_runs.title` + tab naming. e2e: tree markup order (Scratch → repo → work → session),
   new-work creates task+root run, run rename persists.
2. **P — in-place sessions**: launch flag, marker reuse, affordance hiding, working-diff view,
   IN_PLACE_BUSY guard. e2e: in-place run has no branch, merge endpoints refuse, second
   in-place agent 409s while first lives, hand session unaffected.
3. **W — WORK.md**: storage + viewer editing + launch/steer injection. e2e: edit → next
   launch's prompt contains the block; no `.coxpit/work` leakage into any git status.
4. **S — Scratch + promotion** (both paths + outside-path warning). e2e: re-parent moves the
   task in `/api/fleet`; register-and-reparent round-trip.
5. **B + Part A surfaces**: ⌘K board entries, copy/positioning sweep; the v5.28 Agents rail
   lands grouped by Project ▸ Work (joins v5.28 phase 3–4). Cut **6.0** here.

## Guardrails

- **No new tables.** One column (`agent_runs.title`); everything else reuses repos/tasks/runs,
  the sessions bucket, root-session semantics, the file-viewer, the spawn.json watcher.
- In-place: never two live agents in one checkout (hard guard, honest 409).
- WORK.md never enters a diff (data-dir canonical; worktree copies under `.coxpit/`, already
  excluded).
- Board untouched functionally; no route removed; shares/archive keep working.
- Session-restore compatibility is a phase-1 e2e assertion, not an afterthought.
- The tree renders from `/api/fleet` data it already has — no N+1 endpoints.
- **Design compliance is gated, not hoped for** (this milestone is likely fleet-implemented,
  and a context-poor implementer redraws UI): every implementation prompt carries the design
  preamble (design/README #13 — spec section + DESIGN.md rules + named seams); the e2e
  **design ratchet** fails the suite if hard-coded hex colors grow in board/cockpit/login
  (extend DESIGN.md + bump the baseline consciously, in the same commit); the diff review
  against the approved 시안 is the last gate. Inject → enforce → review.

## Definition of done

- The motivating example is literally reproducible: register `coxpit-oss`, create work
  `기능 업데이트 6.0` (a `main` terminal opens at the checkout), add `구현 · opus` in-place and
  `기타 · opus` in a worktree — the tree shows exactly that shape, tabs read `구현`, `기타`.
- The in-place agent's edits are visible live from the `main` terminal; launching a second
  in-place agent is refused with the steer-or-worktree hint.
- A decision written into WORK.md from the cockpit appears in the next agent's prompt.
- A scratch session promotes into a project without losing its terminal.
- The board still answers on `/`; ⌘K reaches Archive; nothing regressed in the board e2e set.
- Full e2e green; cockpit JS passes `node --check`; typecheck clean.
