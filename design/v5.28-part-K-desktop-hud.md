# v5.28 Part K — the desktop HUD (floating mini window + hotkey)

> Ambient agent-fleet awareness **without the menu bar**. A small always-on-top window you glance
> at (a collapsed pill near the notch), expand into a triage list, and drill into a selected agent
> or session — deciding right there, opening the full cockpit only as a last resort.

## Why (owner, from use)

The menu bar was the obvious macOS home for ambient status, but the owner's menu bar is **full and
notched** — a new status item overflows/hides behind the notch, so "glance" becomes "can't see it."
So the HUD is a **self-drawn floating window** (what the owner first reached for as a "Dynamic
Island"). There is no native macOS Dynamic Island; third-party apps just draw their own overlay —
we do the same, deliberately, because the menu bar doesn't fit this user.

It is the surfacing layer for what Part A already computes (agent state), reusing Part C (quick
replies / steer), Part E (activity view / humanize / diff), Part H (dry). **The daemon does not
change** beyond serving one new page; the HUD reads the same `/api/fleet` + `/ws` + existing action
endpoints.

Mockup (iterated with the owner): Artifact `e4548818` — collapsed pill · expanded triage list ·
row-select → **master-detail side-by-side** · all-clear · hidden mode.

## Shape (three visual states, one window)

1. **Collapsed pill** (ambient) — a tiny pill parked near the notch: state dots (working blue /
   waiting amber-pulse / idle grey) + a waiting count. Draggable to any position. This is the
   glance; it is all that shows at rest.
2. **Expanded — triage list** — click the pill (or hotkey): the window grows to a narrow list.
   **Needs-you leads** (waiting agents on top), running is a folded summary, idle/done are a count.
   When nothing waits, a calm **all clear** summary instead of an empty list.
3. **Expanded + detail (side-by-side)** — select a row: the window **widens** and a **detail pane
   opens to the right of the list** (master-detail, both visible). `esc` closes the detail only,
   keeping the list. Detail content depends on what's selected (K5).

Two modes, a setting: **ambient** (pill always visible) ↔ **hidden** (nothing on screen; the hotkey
summons the expanded window, `esc` hides it again). Menu bar is never used.

## K1. The window (`desktop/main.cjs`) — **shipped**

- A **third `BrowserWindow`** (main window + auth prompt already exist), created frameless,
  transparent, `alwaysOnTop:true` (`'floating'` level), `resizable:false`, `skipTaskbar` where
  applicable, no shadow bleed (see [[reference_electron_overlay_window]] — `hasShadow` gotcha).
  It loads **`${boardOrigin}/hud`** (the embedded/attached daemon, same origin as the main window,
  so auth/cookies/WS are shared — reuse `boardOrigin`, `probeHealth`, the `app.on('login')` path).
- **Persists when the main window is closed.** Today closing the window can end the app; gate quit
  on *both* windows being gone (and honor the ambient/hidden setting). The daemon keeps running
  (it already outlives the window via the lock/attach model) — the HUD just keeps reading it.
- **Sizing** = three fixed heights/widths the main process sets on the window as state changes
  (collapsed pill ≈ 120×26 · expanded list ≈ 250×N · expanded+detail ≈ 570×N). The page requests a
  resize over a tiny IPC (`ipcMain` already wired) or the main process observes a `postMessage`.
- **Drag**: the pill/header uses `-webkit-app-region:drag`; remember the last position per display
  (`screen` module), restore on show. Interactive controls set `-webkit-app-region:no-drag`.
- **Per-display**: show on the display with the cursor (or the last-used one); clamp near the top,
  offset from the notch. Multi-monitor is a real case for this owner.

## K2. Modes + hotkey (`desktop/main.cjs`, `globalShortcut`) — **shipped**

- Setting `hud.mode` = `ambient` | `hidden` (persisted in the desktop app's store; default
  **ambient**). Ambient: the collapsed pill is always shown. Hidden: the window is hidden; only the
  hotkey brings it up (expanded), and `esc`/blur hides it again.
- **Global shortcut** (default `Cmd+Shift+\`, rebindable): toggles expand/collapse in ambient mode;
  summons/hides the expanded window in hidden mode. Register via `globalShortcut` (already imported
  region exists — add it). A second shortcut (optional) "jump to next waiting" focuses the HUD on
  the next `waiting` agent.
- The HUD must not steal focus destructively — showing it should not disrupt the frontmost app more
  than necessary (`showInactive` for ambient repaints; focus only when the user summons/acts).

## K3. Collapsed pill (`src/hud.ts`, new served page)

- Glance content from `/api/fleet` + `agentstate` deltas (Part A): **state dots** for the live mix
  and a **waiting count** when > 0. Amber pulse when any agent is `waiting`; otherwise quiet.
  Nothing else — no labels (that was the mockup annotation, not UI).
- Colors are the existing tokens exactly (working `--running`, waiting `--blocked`, idle `--faint`,
  exited `--done`). No new colors, no emoji — mono glyphs only, same discipline as cockpit/board.
- Click → expand (resize + render list). The whole pill is a drag handle except the click target.

## K4. Expanded — triage list (`src/hud.ts`)

- **Header** leads with `N needs you` (amber) when waiting > 0, else `all clear` (green). A compact
  `· M running · K idle` follows.
- **Needs you** section first: one row per `waiting` agent (role name + repo▸task), amber, pulsing
  dot. This is the reason the HUD exists (Part A: get pulled back only when one needs you).
- **Running** section: folded summary (`Running N`), slim rows (name + current activity +
  elapsed), no actions — click to select. `dry` runs show the `dry` chip (Part H). idle/done: a
  one-line count.
- **All clear** (waiting == 0): replace the list body with a calm summary (running rows + counts),
  not an empty list — the tone tracks state.
- Keyboard: `j`/`k` move selection, `enter` selects (opens detail K5), `y`/`n`/`c` act on a
  highlighted waiting row inline (Part C quick replies), `esc` collapses.

## K5. Row select → detail pane, side-by-side (`src/hud.ts`)

Selecting a row widens the window and opens the **detail column to the right of the list** (both
visible). Content by kind — all from data the client already has, reusing existing endpoints:

- **Waiting agent** — the pending question big + `승인`/`거절`/`계속` (`y`/`n`/`c`, Part C over the
  `{t:'i'}` / steer path), the identity line (repo▸task · model · branch), **최근 활동** (Part E
  humanized timeline, last few), a **change** line (`filesChanged` + a `diff` peek reusing
  `/api/runs/:id/diff`), a **Steer** input (one-line follow-up, Part C), and `코크핏에서 열기` /
  `정지`(stop). Never fabricate the question — it comes from the parsed prompt / `latestActivity`;
  if none, say so.
- **Running agent** — no question card; the **Now** line + mini timeline + **Steer** input +
  `코크핏에서 열기` / `정지`. Same reuse.
- **Session** (free terminal, `runIsSession`) — no agent, so: the **terminal tail** (last lines,
  read-only, from the existing scrollback endpoint) + `터미널 열기`(cockpit) / `이름변경` / `삭제`
  (the existing `DELETE /api/runs/:id` session path). No question/steer.

`코크핏에서 열기` is the escape hatch to the full cockpit (Part E activity view); the HUD's job is to
let you finish most things **without** it. `esc` closes the detail, keeps the list.

## K6. Data & reuse (no new daemon endpoints if avoidable)

- Reads: `GET /api/fleet` (+ `real`, agentstate) and the `/ws` deltas — exactly what the cockpit
  reads. The HUD **excludes nothing the cockpit shows** except it *includes* sessions in the list
  (they get the session detail); it is the cockpit's data, re-surfaced small. (Note: Part I removed
  sessions from the **board**; the HUD is not the board — sessions belong here as a selectable kind.)
- Actions call existing endpoints only: quick replies / steer (Part C, the `{t:'i'}` input +
  `/api/runs/:id/steer`), stop (`stopRun` route), session delete (`DELETE /api/runs/:id`), diff
  (`/api/runs/:id/diff`). The pending-question text reuses Part A/`latestActivity` + the run's tail.
- New surface only: `src/hud.ts` (self-contained HTML string like `board.ts`/`cockpit.ts`, **no
  build step**, mono, existing tokens) + `GET /hud` in `server.ts` (served like `/cockpit`, same
  auth gate). Optionally a tiny IPC for window-resize requests.

## K7. Honesty & scope

- **No menu bar.** A self-drawn floating window (deliberate — the menu bar doesn't fit a full/notched
  bar). It is not a native Dynamic Island; it draws its own surface.
- **Daemon unchanged** beyond serving `/hud`. No schema change, no new action endpoints — reuse
  Part A/C/E/H. No new colors, **no emoji** (cockpit/board/login/hud all mono — the emoji gate
  should extend to the served `/hud`).
- **No fabricated state** — states from Part A (positive pattern only), questions from the parsed
  stream; when unknown, say so.
- The pill never nags in quiet times (idle = quiet); it pulses only on `waiting`. Attention sound/
  notification is opt-in, reusing Part A A5.
- Windows/Linux: the floating window works cross-platform; the notch-parking is macOS-flavored but
  degrades to a normal top-corner float elsewhere.

## K8. DoD

- A frameless always-on-top HUD window loads `/hud`, persists when the main window is closed, and is
  draggable + per-display.
- Ambient shows a collapsed pill (glance: dots + waiting count, amber pulse on waiting); the hotkey
  toggles expand/collapse; hidden mode shows nothing until summoned.
- Expanded = triage list (needs-you leads, running folded, all-clear when quiet); selecting a row
  opens a side-by-side detail (waiting / running / session variants) with inline decide + steer +
  open/stop, reusing Part A/C/E/H endpoints.
- Keyboard: hotkey toggle/summon · j/k · enter · y/n/c · esc.
- `/hud` is mono, uses only existing tokens (design ratchet unmoved), emoji-free (gate extended);
  `npm run typecheck` clean; full e2e green (new `/hud` markers + a served-page check).

## Shipped

**K3–K7** (the served `/hud` page) and **K1/K2** (the floating window + the global hotkey) are both in.
Notes from building K1/K2, because they are the parts a re-read would get wrong:

- The window drives the page **through the keyboard the page already had** (`Enter` expands the pill,
  `Escape` closes one layer, sent with `executeJavaScript` + a synthetic `KeyboardEvent`). There is no
  second command channel, so `/hud` still contains **zero** lines of desktop code — the only bridge is
  one-way and upward: `window.coxpitHud.size({state,w,h})`, guarded on its own existence.
- Sizes are **requested by the page, granted by the main process** — which alone calls `setBounds`,
  grows from the current corner, and clamps into the display `workArea`. The pill reports a *measured*
  width (its dot count changes it); the list/detail report the fixed table. Both sides keep the same
  table so a missing report still lands on the right size.
- `hasShadow:false` is not cosmetic — with a transparent window the OS paints a **square** shadow
  outside the rounded pill. Position is remembered **per display id**; the summon lands on the display
  under the cursor. Ambient shows with `showInactive()` and only a user summon takes focus.
- Quit is gated on both windows, and `activate` now judges by the **main** window — the HUD keeps the
  window count above zero forever, so the old `getAllWindows().length === 0` check would never fire.
- `코크핏에서 열기` navigates the **main** window (`will-navigate` → `openInMainWindow`); a 120px pill
  must never become a cockpit.
- **Not done (deliberate):** the optional second "jump to next waiting" shortcut. Which run is next is
  knowledge the page holds and the window does not, and doing it honestly needs one more channel — it
  is a TODO in `main.cjs`, not a silent omission.
- **Unverifiable here:** e2e cannot launch Electron. The source-level contracts (window flags, the
  bridge, the shortcut, the quit gate) are pinned in `test/e2e.sh`; the *behavior* is the owner's to
  confirm by launching the app.
