# v4.1 — the library (detailed design)

Six features. All are independent; land them as separate commits in this order
(snapshots first — B depends on A; the rest are free-standing).

---

## A. Document snapshots

**Problem.** Doc mode reads the live worktree (`getRunDocs`). After merge + Close
task the worktree is gone and a run's document output is unviewable forever.

**Decision.** Snapshot changed docs into the DB at two trigger points:
1. **Settle** — in `runAgentChild` right after the final `setRun({status: done|failed|stopped …})`,
   when `filesChanged > 0`. Best-effort (`void snapshotRunDocs(runId)`), never blocks settle.
2. **Cleanup** — first line of `cleanupRun` before the worktree is removed. This also
   catches hand-edited workbenches (which never "settle").

Latest wins: `snapshotRunDocs` deletes existing rows for the run, then inserts fresh.
If `getRunDocs` returns 0 docs, keep existing snapshots (don't wipe history with an
empty read — e.g. cleanup after the worktree already vanished).

**Schema** (`src/db/schema.ts` + idempotent DDL in `src/db/index.ts`):

```sql
CREATE TABLE IF NOT EXISTS doc_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  run_id INTEGER NOT NULL,
  path TEXT NOT NULL,
  kind TEXT NOT NULL,              -- 'md' | 'html'
  content TEXT NOT NULL DEFAULT '',
  created_at INTEGER DEFAULT (unixepoch())
);
```

Caps: reuse `getRunDocs` limits (6 files, 200KB each — it already enforces both).

**Orchestrator** (`src/orchestrator.ts`):

```ts
export async function snapshotRunDocs(runId: number): Promise<void> {
  const d = await getRunDocs(runId).catch(() => null);
  if (!d?.ok || d.docs.length === 0) return;          // empty read keeps old snapshots
  await db.delete(docSnapshots).where(eq(docSnapshots.runId, runId));
  for (const doc of d.docs) await db.insert(docSnapshots).values({ runId, ...doc });
}
```

**API** — `GET /api/runs/:id/docs` gains a fallback and a `source` field:

```
200 { ok: true, docs: [{path, kind, content}], source: 'worktree' | 'snapshot' }
```

Logic: try `getRunDocs`; if `!ok` **or** `docs.length === 0`, read `doc_snapshots`
for the run; if snapshot rows exist → `source:'snapshot'`. If neither → current
behavior (`ok:true, docs:[], source:'worktree'`).

**Board** (`src/board.ts`):
- `loadDiff()` currently hides `#mDocsTgl` from the diff stat regex. Change: when
  the diff call fails (worktree gone) OR stat has no doc extensions, additionally
  `fetch('/api/runs/'+id+'/docs')` and show the toggle if `docs.length > 0`.
  (One extra request only on runs without a live doc-bearing worktree — acceptable.)
- `paintDocs()` shows a provenance line when `source === 'snapshot'`:
  `<div class="doc-src">worktree gone — snapshot taken at settle</div>`
  CSS: `.doc-src{font-family:var(--mono);font-size:10.5px;color:var(--faint);margin-bottom:10px}`

**e2e** (extend the existing docs check, which already writes `REPORT.md` into `$WT2`):
after that check passes → `POST /api/runs/2/cleanup` → `GET /api/runs/2/docs` →
assert `"source":"snapshot"` and `Hello Doc` still present. (Cleanup trigger covers
the snapshot path without needing a settle-time hook in dry timing.)

## B. Share pages render documents

**Decision.** `/share/<token>` gains a **Documents** section between the summary and
the Timeline. Data source: same fallback chain as the API (live worktree → snapshots).

**Server** (`src/server.ts`):
- Port the board's `mdLite` to the server as `mdLiteHTML(src: string): string`.
  Supported syntax (match the board version exactly — read it, don't reinvent):
  `#`/`##`/`###` headings, `**bold**`, `` `code` ``, `-`/`*` lists, paragraphs.
  All text HTML-escaped first (`escH`), then markup applied.
- In the `/share/:token` handler: `const docs = …` (getRunDocs → snapshots fallback);
  pass to `sharePageHTML`.
- `sharePageHTML` renders per doc:
  - `md` → `<div class="doc"><div class="doc-h">{path}</div><div class="doc-b">{mdLiteHTML(content)}</div></div>`
  - `html` → `<iframe sandbox="" srcdoc="{escH(content)}" class="doc-frame"></iframe>` (height 420px)
  - CSS mirrors the board's `.doc-md` rules (see board styles `doc-md h1…p`).

**e2e**: in the share check, before creating the link, `REPORT.md` already exists in
`$WT2`; assert the share page contains `Hello Doc` (rendered section).

## C. Per-launch model choice

**Decision.** Free-text model per launch (CLI model names change too fast for a
hardcoded list) + last-5 recall via localStorage. Empty = CLI default (today's
behavior, unchanged).

**Schema**: `agent_runs` + `model TEXT NOT NULL DEFAULT ''` (idempotent ALTER).

**Validation** (server, at `/api/tasks/:id/run`): trim; max 64 chars; must match
`/^[\w.\-:\/]*$/` (shell-safe charset) else 400. Store on every created run.

**Provider seam** (`src/providers.ts`) — signature change:

```ts
launchCmd(prompt: string, model?: string): string
resumeCmd(sessionId: string, message: string, model?: string): string
```

- claude: append ` --model ${shq(model)}` when model non-empty.
- codex: insert ` -m ${shq(model)}` among the exec flags (BEFORE `resume` in resumeCmd).

**Orchestrator**: `launchRun` passes `run.model`; `steerRun` passes `run.model`
(sessions keep their model). `spawnSubtasks` copies the parent run's `model` onto
child runs (inheritance). Dry-run ignores model (mock path).

**Board**:
- Task panel, directly under `#provSeg`:
  ```html
  <p class="flabel">model · optional</p>
  <input id="taskModel" placeholder="CLI default" list="modelHist" />
  <datalist id="modelHist"></datalist>
  ```
- Submit: include `model: $('taskModel').value.trim()` in the `/run` body.
  On success, persist to localStorage `coxpit.models` (dedup, newest first, cap 5)
  and repaint the datalist.
- Card meta: when `r.model` non-empty append `<span>⚙ {model}</span>`.

**e2e**: launch a dry run with `"model":"test-model-x"` → run row carries
`"model":"test-model-x"`; launch with `"model":"bad space"` → 400.
Provider unit block (the existing `prov.test.ts`): `launchCmd('p','opus-x')`
contains `--model 'opus-x'`; codex `resumeCmd('id','m','gpt-x')` matches
`/exec --json --sandbox \S+ -m 'gpt-x' resume /`.

## D. Close-task guard

**Problem.** Close task deletes worktrees; done-but-unmerged output dies silently
(real incident: a roadmap doc nearly lost).

**Decision.** Server-side risk check on close; board confirms with a danger dialog.

**Risk definition** (per run of the task): status ∈ {done, failed, stopped}
AND `filesChanged > 0` AND status ≠ merged AND the run has **no** `export` and
**no** `pr` event (query `agent_events` kinds for the run).
(merged runs and 0-change runs are safe; export/PR mean the output escaped.)

**API**: `POST /api/tasks/:id/close` — body `{force?: boolean}`.
- If at-risk runs exist and `!force` → `409 { error:'unmerged output', atRisk:[{runId, filesChanged}] }`.
- `force:true` → close as today.

**Board**: close-task handler — on 409 with `atRisk`, show
`confirmUI('Close and delete unmerged output?', { danger:true, sub:'r7 · 1 file — not merged, not exported. Worktrees are deleted on close.', okLabel:'Close anyway' })`
(list every at-risk run in `sub`, joined by ' · '); on OK retry with `{force:true}`.

**e2e**: task with a dry run (has `COXPIT_DRYRUN.txt`, unmerged) → close without
force → expect 409 with `"atRisk"`; close with `{"force":true}` → 200.
The existing "task close cleans worktrees" check must be updated to pass `force:true`
(its runs are intentionally unmerged).

## E. Per-repo base branch override

**Problem.** Detected default (main) is wrong for develop-flow repos; merge guard
then rejects everything (real incident: budget-ops).

**API**: `PATCH /api/repos/:id` — body `{defaultBranch: string}`.
Validation on the repo's machine:
`git -C <path> rev-parse --verify --quiet refs/heads/<branch>` (shq both) — exit 0
required, else `400 { error: "branch 'x' not found in the repository" }`.
Branch name charset guard first: `/^[\w.\-\/]{1,80}$/`.

**Board** (CONTEXT section): next to the existing Browse/Path/× row add a ghost
button `⎇` (`id="repoBranch"`, title "change the base branch — merges, Sync base
and PRs all target it"). Click → `.cfm` dialog (clone `#ghOverlay` pattern):
one input prefilled with the current `defaultBranch`, OK → PATCH → toast + hydrate.

**Downstream** — no orchestrator change needed (`ctx.baseBranch` already reads
`repo.defaultBranch`), but audit these three places and confirm they use it:
merge guard (`mergeRun`), `syncRun`, and worktree base in `launchRun`.
**One real change**: `prRun` must pass `--base <defaultBranch>` to `gh pr create`
(today it inherits GitHub's default).

**e2e**: PATCH repo 1 to `wip-side-branch` (exists in the fixture repo) → 200 and
repos list reflects it; PATCH to `no-such-branch` → 400; PATCH back to `main`.

## F. Closed-card hatching

**CSS** (board):

```css
.card.closed{opacity:.6;filter:saturate(.45)}
.card.closed .log{position:relative}
.card.closed .log::after{content:'';position:absolute;inset:0;pointer-events:none;
  background:repeating-linear-gradient(135deg,transparent 0 9px,rgba(255,255,255,.035) 9px 11px)}
.card.closed .log::before{content:'CLOSED';position:absolute;top:50%;left:50%;z-index:1;
  transform:translate(-50%,-50%) rotate(-7deg);font-family:var(--mono);font-size:15px;
  letter-spacing:.34em;color:var(--faint);border:1px solid var(--line-hi);
  border-radius:6px;padding:4px 14px;background:rgba(11,13,18,.72)}
```

**JS**: `cardHTML` already computes `closed` — add `(closed?' closed':'')` to the
card's class attribute. Keep the existing `· closed` title suffix (screen readers).
Status chips remain untouched.

**e2e**: board HTML contains `card.closed .log::before` (style presence check).
