# v4.4 — greenfield + batch riders (detailed design)

Three parts, one release. Part A is the floor (a real first-run bug), Part B is
the feature it unlocks, Part C is an unrelated small rider batched into this train.

Pinned behaviors (verified live on git 2.50 / tailnet mini, 2026-08-19):
- On an **unborn branch** (repo with zero commits): `git symbolic-ref --short HEAD`
  → prints `main`, exit 0. `git rev-parse --verify -q HEAD` → exit 1.
  `git rev-parse --abbrev-ref HEAD` → `fatal: ambiguous argument 'HEAD'` (the bug).
- After `git commit --allow-empty`, `git worktree add -b <branch> <path> main` works.

---

## Part A — floor: commitless repos are handled, not corrupted (backlog B1)

**Problem.** Registering a repo with zero commits: the default-branch detection's
last fallback (`git rev-parse --abbrev-ref HEAD`, `src/server.ts` register route)
errors with `fatal: ambiguous argument 'HEAD'`, the repo still registers
(`register: true`) with a garbage `defaultBranch`, and every later worktree/merge
breaks. Reported live 2026-08-19.

**Changes** (`src/server.ts`, POST `/api/repos` — the detection chain around
"기본 브랜치는 ... 진짜 기본값" comment):

1. Replace the last fallback and add a commit-presence marker. New chain:

```ts
const cmd =
  `${g} rev-parse --is-inside-work-tree 2>&1` +
  ` && echo '---B---'` +
  ` && { ${g} symbolic-ref --short refs/remotes/origin/HEAD 2>/dev/null || true; }` +
  ` && echo '---C---'` +
  ` && { ${g} show-ref --verify -q refs/heads/main && echo main || { ${g} show-ref --verify -q refs/heads/master && echo master; } || true; }` +
  ` && echo '---D---'` +
  ` && { ${g} symbolic-ref --short HEAD 2>/dev/null || true; }` +   // unborn에서도 무에러
  ` && echo '---E---'` +
  ` && { ${g} rev-parse --verify -q HEAD >/dev/null 2>&1 && echo yes || echo no; }`;
```

2. Parse `hasCommit = (---E--- 뒤 세그먼트) === 'yes'`. `headNow` 는 이제
   `---D---`~`---E---` 세그먼트.
3. If `!hasCommit` → **register is refused**:

```
400 { error: 'this repository has no commits yet',
      code: 'NO_COMMITS',
      hint: 'make an initial commit first — or use Start a new project to have coxpit do it' }
```

Rationale: a commitless repo cannot host worktrees (nothing to branch from);
silently registering it is corruption, not tolerance.

**Board** (`src/board.ts`, `#repoForm` submit handler — the fetch to POST
`/api/repos`): when the response is 400 and `j.code === 'NO_COMMITS'`, do NOT
just toast. Offer the ceiling:

```js
const yes = await confirmUI('This folder has no commits yet — start a new project here?',
  { sub: 'coxpit will create an empty initial commit as the base, then register the repo. The folder itself is untouched.', okLabel: 'Start new project' });
if (yes) { /* POST /api/repos/new with the same path (Part B) → 기존 성공 처리 재사용 */ }
```

## Part B — greenfield: Start a new project

**Concept.** N agents scaffold a brand-new project in parallel; you compare the
foundations and merge the winner onto an empty `main`. The empty initial commit
is the base worktrees branch from — the rest is the existing fleet flow untouched.

### API — `POST /api/repos/new`

Body: `{ machineSlug: string, path: string, name?: string }`

Validation order (each failure = its own clear error):
1. `machineSlug`/`path` required; `path` must be absolute (`startsWith('/')`) → 400.
2. machine lookup → 404.
3. On the machine, one shell chain (20s timeout) that classifies the path:

```ts
const g = `git -C ${shq(path)}`;
const probe =
  `if [ ! -e ${shq(path)} ]; then echo MISSING;` +
  ` elif [ ! -d ${shq(path)} ]; then echo NOTDIR;` +
  ` elif [ -d ${shq(path)}/.git ]; then { ${g} rev-parse --verify -q HEAD >/dev/null 2>&1 && echo REPO_HAS_COMMITS || echo REPO_EMPTY; };` +
  ` elif [ -z "$(ls -A ${shq(path)} 2>/dev/null)" ]; then echo EMPTYDIR;` +
  ` else echo NONEMPTY; fi`;
```

Decision table:
| probe | action |
|---|---|
| `MISSING` | `mkdir -p` → init+seed → register |
| `EMPTYDIR` | init+seed → register |
| `REPO_EMPTY` (git repo, 0 commits) | seed only (커밋만) → register |
| `REPO_HAS_COMMITS` | 409 `already a repository with commits — use Register` |
| `NONEMPTY` | 409 `folder is not empty — greenfield never touches existing files` |
| `NOTDIR` | 400 `path is not a directory` |

Guardrail (문서에도 명시): **greenfield never `git init`s a populated folder** —
someone's files must not become a repo by surprise. This endpoint is the only
place coxpit ever runs `git init`, and only on MISSING/EMPTYDIR/REPO_EMPTY.

init+seed (one chain, coxpit ident, gpgsign off — mergeRun과 동일 관례):

```ts
const seed =
  `mkdir -p ${shq(path)} && cd ${shq(path)}` +
  ` && { [ -d .git ] || git init -b main; }` +
  ` && git -c user.name='coxpit' -c user.email='coxpit@local' -c commit.gpgsign=false` +
  ` commit --allow-empty -m 'coxpit: initial commit'`;
```

Then insert the repos row directly (`defaultBranch: 'main'` — detection unnecessary,
we just made it) and return `201 { ok: true, repo }` (same shape as Register).
`name` defaults to the last path segment (Register와 동일 규칙).

REPO_EMPTY 케이스의 브랜치명 주의: 기존 unborn 브랜치가 master 일 수 있음 —
seed 후 실제 브랜치를 `git symbolic-ref --short HEAD` 로 읽어 그 값을
`defaultBranch` 로 저장한다 (init 케이스는 항상 main).

### Board — launcher entry

1. CONTEXT의 repo 버튼 행(`Browse… / Path / ⎇ / ×`)에 **`New`** ghost 버튼 추가
   (`id="repoNew"`, title "start a new project — empty folder in, scaffolded repo out").
2. Dialog `#npOverlay` (`.cfm` 패턴 — `#ghOverlay` 클론):
   - 제목 "Start a new project"
   - 설명(`.s`): "Creates the folder if needed, then git init + an empty initial
     commit as the base. Never touches non-empty folders. Then: write a task like
     'scaffold a … app', run a fleet of 2–3, and compare the foundations."
   - 입력: `#npPath` (placeholder `/abs/path/to/new-project`) · `#npName` (optional)
   - OK → POST `/api/repos/new` (machineSlug = 현재 선택 머신) → 성공 시 toast
     "project ready — write a scaffold task and Run fleet", hydrate 후
     `$('taskRepo').value = repo.id` 로 새 repo 자동 선택(+ `dressSelect`/`syncSelect` 동기화).
   - 409/400 은 `j.error` 그대로 toast.
3. Esc 핸들러 목록에 `#npOverlay` 추가 (기존 overlay 나열 라인).
4. Part A 의 NO_COMMITS confirm 흐름도 이 POST 를 재사용.

### DESIGN.md rows

- New project | `#npOverlay` + `New` in Context | the only place coxpit ever
  runs `git init`; empty/missing/commitless paths only — a populated folder is
  never initialized; success auto-selects the repo
- Commitless register | `NO_COMMITS` 400 → confirm offers greenfield | register
  never silently stores a broken defaultBranch

## Part C — rider: strip ANSI from session model names (backlog B2)

**Problem.** Timeline session line renders `started · claude-opus-4-8[1m]` — an
ANSI bold code rides in the model string (spotted in demo GIF capture). Display
only, but it shows up in marketing assets.

**Fix at the source** (`src/providers.ts`, claude `parseLine`): system 이벤트는
full fidelity 가 필요 없다 — **길이와 무관하게 항상 컴팩트 재직렬화**로 통일하고
그 시점에 model 을 소독한다. `obj.type === 'system'` 처리에:

```ts
const stripAnsi = (x: string) => x.replace(/\[[0-9;]*m/g, '');
// system 은 항상 압축 저장 (긴/짧은 라인 동일 경로 — 기존 >2000 분기의 system 케이스를 승격)
if (obj.type === 'system') {
  stored = JSON.stringify({ type: 'system', subtype: obj.subtype,
    model: typeof obj.model === 'string' ? stripAnsi(obj.model) : obj.model });
}
```

(`session_id` 캡처는 stored 와 무관하게 기존 위치 유지 — sessionId 는 ev 필드다.)

**Belt at display** (`src/board.ts` `humanize`, session 분기): 이미 저장된 오염
행(상주 DB)을 위해 표시 시에도 한 번 더:

```js
if (o.subtype === 'init' || !o.subtype) return { k:'session',
  t:'started'+(o.model?' · '+String(o.model).replace(/\\u001b\\[[0-9;]*m/g,'')
                                             .replace(/\\x1b\\[[0-9;]*m/g,'') : '') };
```

주의(보드 이스케이프 규칙): board.ts 템플릿 리터럴 안 정규식이므로 소스에는
`\\u001b` 형태로 써야 클라이언트에 `` 로 전달된다 — design/README.md
함정 #1. 간단히 하려면 정규식 대신 `split(String.fromCharCode(27))[0]` 방식도 허용.

## e2e additions (모두 dry, 크레딧 0)

1. **A**: fixture 로 커밋 없는 repo 생성(`git init -qb main`만) → POST /api/repos
   → `400` + body 에 `NO_COMMITS`.
2. **B 성공 경로**: `POST /api/repos/new` (미존재 경로) → 201 + `"defaultBranch":"main"`;
   그 repo 에 태스크 + dry run 1개 → settles done + diff 에 `COXPIT_DRYRUN` —
   **빈 초기 커밋이 worktree base 로 성립함을 증명**. close(force)로 정리.
3. **B 가드**: `POST /api/repos/new` 를 (a) 파일이 있는 비어있지 않은 폴더 → 409,
   (b) 커밋 있는 기존 repo 경로 → 409, (c) 상대경로 → 400.
4. **C**: provider unit(`prov.test.ts`)에 추가 — claude provider 로
   `parseLine('{"type":"system","subtype":"init","model":"m[1mx"}')` →
   `stored` 에 `` 부재 && `m` 과 `x` 포함.
5. 보드 자산: `id="npOverlay"`, `id="repoNew"` presence.
