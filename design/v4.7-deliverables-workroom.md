# v4.7 — deliverables & the converge workroom (detailed design)

Two paired features that reframe a run around its **deliverables** and make the Goal
workroom the place you **converge** them.

1. **Deliverable contract + output cards.** A task can declare the outputs it must
   produce (answer / code / doc / page / file). The run is instructed to produce them and
   **register each in a manifest**; on settle coxpit pins exactly those as **output cards**.
   The run modal becomes: **timeline (left) · output cards (right)**, and clicking a card
   opens its **real viewer** (rendered markdown, a live sandboxed HTML page, a colored diff,
   an image preview) — diff is demoted to one card among several.
2. **Converge cockpit.** The Goal workroom's Work body becomes per-run decision rows —
   review / fix (steer) / **merge** / **close** each run from one session, with the output
   cards as the review peek. Group bar: Integrate selected · Review group · Close group.

**Visual source of truth (approved):** `scratchpad/goal-converge-artifact.html` and
`scratchpad/goal-outputs-artifact.html` (hosted artifacts). Match layout + the board's
existing tokens (`--brand #4ec9b0`, `--s-*`, `.chip`, `.seg`, `.btn`, `.card`).

**Everything reuses existing renderers** — no new deps, board stays one framework-free HTML
string. Confirmed present: `mdLite` (board.ts:1792 + `mdLiteHTML` server.ts:38), HTML sandbox
(`<iframe sandbox srcdoc>` board.ts:1490), colored diff (`getRunDiff` + `<pre class=diff>`),
doc snapshots (v4.1, `doc_snapshots`), the final answer (`result` event `resultText`,
providers.ts:78). **Only new capability: serving a run file's bytes** (for image previews).

Ships as **4.7.0** (bundles nothing else pending; feature = minor bump).

## Output taxonomy (the 5 card types)

| type | source (existing) | real viewer |
|---|---|---|
| `answer` | final `result` event text (+ last assistant msg) | rendered markdown (`mdLite`) |
| `code`   | `getRunDiff` (non-doc changes) | colored per-file diff (existing `<pre class=diff>`) |
| `doc`    | changed `.md` via `loadRunDocs` (worktree→snapshot) | rendered markdown (`mdLite`) |
| `page`   | changed `.html` via `loadRunDocs` | **live** sandbox iframe (`srcdoc`, no scripts loaded cross-file) |
| `file`   | other new/changed files (`git status --porcelain`) | image → `<img src=/api/runs/:id/file>`; else download + (small text → mono) |

A **declared** task output is one of these types the task must produce (`required`). Anything
the run produced beyond the declared set shows as **부수 (incidental)**.

## Part A — the deliverable contract (`orchestrator.ts`, `db`)

### A1. Schema
- `tasks.outputs TEXT NOT NULL DEFAULT '[]'` — JSON array of declared types, e.g.
  `["answer","doc","page"]`. Idempotent DDL in `db/index.ts`; column in `schema.ts`.
- No new table. The per-run captured outputs are derived on read (not stored), except doc
  snapshots which already persist md/html.

### A2. Manifest convention — `.coxpit/outputs.json`
Same file-protocol family as `spawn.json`/`subtasks.json` (already in `info/exclude`). The
agent writes an array of its deliverables:
```json
[ { "path": "REPORT.md", "type": "doc", "title": "3-approach comparison" },
  { "path": "comparison.html", "type": "page", "title": "Comparison table" } ]
```
`answer` needs no path (it's the final message). Optional but preferred — coxpit falls back
to git-status categorization when it's absent (robust to agents that ignore it).

### A3. Prompt injection
When `task.outputs` is non-empty, `launchRun`/`launchGroupTask` append to the agent prompt
(via the provider launch, same place designCapture context is injected):
```
Deliverables (required): <human list, e.g. "an answer, a Markdown doc, an HTML page">.
Produce each as a real file in the repo (docs as .md, pages as .html). Register every
deliverable in .coxpit/outputs.json as a JSON array of {path,type,title}. End with a final
message stating the answer.
```

### A4. Capture + validate — `computeRunOutputs(runId)` (new export)
On demand (and cached cheaply). Returns the ordered card list:
1. Read `.coxpit/outputs.json` from the worktree (if present) → declared deliverables.
2. `git status --porcelain` → changed files; categorize by ext: `.md`→doc, `.html`→page,
   image exts→file(image), other text/code→code (aggregated into the single `code` diff card),
   remaining→file.
3. `answer` = the run's `result` text (from events) if present.
4. Merge manifest + derived; each card: `{type, title, path?, required: type∈task.outputs,
   present: true, meta}`. For each **declared** type with **no** present output → emit a
   `required:true, present:false` placeholder card (the ⚠ "미생성" state).
- Post-cleanup: worktree gone → docs/pages come from `doc_snapshots`; `code`/`file` become
  unavailable (note on the card: "worktree cleaned — snapshot only"). answer persists (events).

### A5. Missing-deliverable policy (defaulted — adjustable later)
- **Default = soft**: a declared-but-missing output renders a ⚠ card + the run card gets a
  small "산출물 미충족" badge. Non-blocking. (Rationale: auto-steering to force output can loop;
  keep the human in the loop.)
- Leave a `// future: strict mode — auto-steer "produce the missing <type>"` comment. Do not
  implement strict now.

## Part B — outputs API (`server.ts`)

- `GET /api/runs/:id/outputs` → `{ outputs: [ {type,title,path?,required,present,meta} ] }`
  (via `computeRunOutputs`). 404 if run missing.
- `GET /api/runs/:id/output?type=<t>&path=<p>` → the **content** for a viewer:
  - `answer`/`doc` → `{ kind:'md', content }` (raw markdown; client renders with mdLite)
  - `page` → `{ kind:'html', content }` (raw html; client sandboxes)
  - `code` → reuse `GET /api/runs/:id/diff` (already exists) — the card links to it
  - Prefer reusing `loadRunDocs` for doc/page content (worktree→snapshot fallback baked in).
- **`GET /api/runs/:id/file?path=<rel>`** (NEW) → raw bytes with `content-type` inferred from
  ext, for image/binary previews. **Guards**: resolve `path` against the run's worktree root,
  reject `..`/absolute/symlink escape (realpath must stay under the worktree); cap size
  (~10 MB); only while the worktree lives (404 after cleanup). Reuse the auth gate.

## Part C — run modal: output cards + real viewers (`board.ts`)

> board.ts is one template literal — client newline `\n`, escaped backticks, `esc()`/`escA()`.
> mdLite (client) and the sandbox-iframe pattern already exist — reuse verbatim.

Redesign the run modal (`openModal`) to the approved outputs 시안:

- **Header** (unchanged): rN · title · status · ×.
- **Contract strip** (new): `요청 산출물(계약): [✓/! type]…  — 부수: [type]…`. `✓` present,
  `!` (warn color) declared-but-missing. Reuse `.req`/badge styling from the mock.
- **Two columns** (`.cols`):
  - **Left `.tl`** — the existing humanized Timeline (reuse current event rendering).
  - **Right `.out`** — default = **cards list** (`GET /api/runs/:id/outputs`), each `.card`
    with typed glyph + title + `요청됨/부수` badge + meta + `›`. Clicking a card → the right
    column swaps to the **detail viewer** with a `‹ 산출물 목록` back:
    - `answer`/`doc` → `<div class="doc-md">${mdLite(content)}</div>` (real markdown render)
    - `page` → `<iframe class="doc-frame" sandbox="" srcdoc="${escA(content)}">` (live page)
    - `code` → the existing diff renderer (colored `<pre class=diff>` with clickable dl-lines)
    - `file`(image) → `<img src="/api/runs/:id/file?path=…">`; other → download link
      (+ small text file → mono `<pre>`)
- **Default open card**: pick by run shape — if a declared `answer`-only/doc run and no code
  changes → open `answer`/`doc`; if code-heavy → `code`; else the first present declared card.
  (Simple heuristic; remember last per session is optional.)
- The old Diff/Rendered toggle is subsumed — diff is the `code` card, Rendered md/html are the
  `doc`/`page` cards. Keep the diff-line-click-to-steer behavior inside the `code` viewer.

### C-req. Request UI — declaring outputs
In the task compose form, add an **outputs selector**: chips/checkboxes
`답변 · 코드 · 문서 · 페이지 · 파일` → `tasks.outputs`. Default: none selected = today's behavior
(no contract; run just shows whatever it produced). Selecting any sets the contract + prompt
injection (A3).

## Part D — converge cockpit (Goal workroom, `board.ts`)

Replace the v4.6 Work-mode feed with the approved **per-run decision panel** (converge 시안).
The workroom already exists (`#groupRoomOverlay`); this restructures its Work body.

- **Group action bar** (top of runs area): `☑ N selected` · `Integrate 선택 (N)` (brand) ·
  spacer · `전체 리뷰` · `그룹 클로즈` (danger). Reuse the existing group select/integrate +
  `reviewTask` loop + group close.
- **Run rows** (`.run`), one per group run:
  - Collapsed head: checkbox (multi-select for Integrate) · status dot · `rN` · title · meta ·
    inline actions `[리뷰] [수정] [머지] [클로즈]` · caret. Merged runs dim + `merged→base`
    badge (actions → `열기`). Running runs: actions locked (`열기 · 정착 후 결정`).
  - Expanded body: the run's **output cards** (Part C, compact) + an inline **수정(steer)**
    input (`→ 세션 이어서`). "리뷰" runs `reviewTask` and shows the ◆ summary here.
  - Actions wire to existing endpoints: `[머지]`→`/api/runs/:id/merge`, `[수정]`→
    `/api/runs/:id/steer`, `[리뷰]`→`/api/tasks/:id/review`, `[클로즈]`→`/api/tasks/:id/close`
    (the run's task; `{force}` guard reused). No new merge/close/review logic.
- Ask mode (L2 coordinator) stays as-is (advisor).

## Phasing (implement in order; each an e2e-green commit)

- **P1 — contract backend**: A (schema, manifest capture, prompt injection, `computeRunOutputs`,
  soft validate) + B (`/outputs`, `/output`, `/file`). e2e: declare outputs on a dry task →
  `/outputs` returns cards with required/present; `/file` guards path traversal; missing
  declared type → `present:false` card.
- **P2 — run modal outputs cards + real viewers + request UI**: C + C-req. e2e (UI contract):
  modal serves contract strip + `#outCards`; request form has the outputs selector. Live-render
  check: answer/doc render as markdown, page as iframe, image via /file, diff as diff.
- **P3 — converge cockpit**: D. e2e: workroom serves the per-run decision rows + group bar;
  per-run merge/close/steer reachable. Live-render: rows expand to output cards + steer.

Each phase: `npm run typecheck` clean + `bash test/e2e.sh` green (bash-3.2 rules) + board JS
parses (no pageerror). No version bump/commit/tag by the implementer — orchestrator (me)
verifies, commits per phase, cuts 4.7.0 after P3.

## Guardrails
- `/api/runs/:id/file` path-escape guard is security-critical (serves arbitrary bytes) —
  realpath under worktree, no symlink/`..` escape, size cap, auth-gated.
- `page` iframe stays `sandbox=""` (no scripts/network) — a "real" render of the markup, not a
  live app with cross-file assets (note this honest limit; multi-file sites won't load siblings).
- No syntax highlighter (no CDN, framework-free) — `code` = colored diff; raw file view is mono.
- Dry-run sacred: `computeRunOutputs` works in dry (mock writes COXPIT_DRYRUN.txt → a `code`
  card; a dry task declaring `doc` with no md → `present:false`). e2e stays credit-free.
- DESIGN.md: add output-card + converge-row components in the same commit.
- Reuse-only for merge/close/review/steer/integrate — no parallel decision logic.

## Definition of done
P1+P2+P3 merged as e2e-green commits; run modal is deliverable-centric with real per-type
viewers; tasks can declare a deliverable contract that pins output cards (⚠ on missing); Goal
workroom converges runs (review/fix/merge/close per run) in one session. Then 4.7.0 cut via the
standard train (bump both package.json + desktop, locks, tag, hardened CI, owner npm publish,
resident upgrade).
